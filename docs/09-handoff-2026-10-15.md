### /loop 部署基础设施（已打通，实测可用）

**背景**：沙盒代理拦截 SSH（22/TCP 被 3128 掐掉），`user-data` 只在首次启动执行。
因此建立了 webhook 部署链：

| 端点 | 方法 | 功能 |
|------|------|------|
| `/deploy?token=xxx` | POST | `git pull` + `pnpm install` + `pnpm build` + 重启服务，202 立刻返回，后台异步执行 |
| `/deploy?token=xxx&rebuild=1` | POST | 同上 + 后台重建 E2B 模板（`REBUILD_TEMPLATES=1`）|
| `/switch-template?token=xxx&template=yyy` | POST | 更新 `.env.production` 的 `E2B_TEMPLATE` 并重启 socket-server |

**鉴权**：`DEPLOY_TOKEN` 明文或 `DEPLOY_TOKEN_HASH`（sha256），另有内置 hash 兜底
（见 `socket-server/src/index.ts` 的 `handleDeploy`，hash 对应的 token 由运维保管，
**不要提交到仓库**）。

**相关文件**：
- `socket-server/src/index.ts`: `handleDeploy()`、`handleSwitchTemplate()`
- `deploy/update.sh`: 部署主脚本（含 SSH key 幂等安装，见下）
- `deploy/switch-template.sh`: 模板切换脚本
- `deploy/ssh-keys/*.pub`: 授权 SSH 公钥（用户 Mac 的 key 已在 `case-mac.pub`）

**Token 保管**：EC2 上的部署 token 存在运维本机的 `~/.config/cassia/deploy-token`
（600 权限），**不要进仓库、不要进记忆**。

## 四、卡点：E2B 模板构建失败

### 症状
`/home/ubuntu/template-build.log`：
```
❌ Template build failed.
Error: No files found in /home/ubuntu/cassia/agent-runtime/src
```

### 根因
仓库根的 `.dockerignore` 是给 socket-server 镜像用的，明确排除了 `agent-runtime/`：
```
# socket-server 镜像只需要根清单 + shared/ + socket-server/
sandbox-lite
sandbox-desktop
agent-runtime    ← 就是这行
...
```
但 E2B 的 `template create` 也尊重 `.dockerignore`，导致
`sandbox-lite/e2b.Dockerfile` 里的 `COPY agent-runtime/src` 找不到文件。

### 修复（已提交，commit e5e57d6，待验证）
`sandbox-lite/build.sh` 和 `sandbox-desktop/build.sh` 在构建时临时移走
`.dockerignore`（`trap` 保证恢复）。

   （或直接在本机用 `curl` 触发：`POST /deploy?token=xxx&rebuild=1`）

## 八、已知坑

1. **沙盒代理禁 SSH**：22/TCP 被 198.19.0.1:3128 拦截，Muse 沙盒内无法 SSH，只能走 webhook
2. **E2B CLI 不走代理**：TLS 会被拦截报错，模板构建必须在 EC2 上做
3. **`.dockerignore` 冲突**：见 §四，E2B 构建和 socket-server 镜像共用一个，已用临时移走方案修复
4. **`update.sh` 的新旧版本问题**：webhook 运行时加载的是旧版脚本，`git pull` 后新逻辑不生效，需要**再触发一次**部署才能用上新脚本
5. **pi 不从 `deepseek/xxx` 反推 provider**：必须显式 `PI_PROVIDER=deepseek` + 裸模型名（否则去 openrouter 找 key）
6. **DeepSeek 当前模型名**：`deepseek-flash`（`deepseek-chat` 是旧名）
