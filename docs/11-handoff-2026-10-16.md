## 本日修复(全部已推 main)

| commit | 问题 |
|---|---|
| `53d16df` | `update.sh` 以 root 运行时 `sudo -E` 保留 `HOME=/root`,ubuntu 身份的 pnpm 读 `/root/.config` 被拒 → 全部 `sudo -H` |
| `d08a907` | Caddy 未反代 `/deploy`、`/switch-template`,webhook 请求落到 Next.js 404(4000 端口不在安全组)→ 补两条 handle |
| `d92bd3e` | webhook 以 ubuntu 身份跑 `update.sh`,`cp /etc/systemd/system` 权限被拒;且 git reset 覆盖运行中的脚本 → 特权操作走 `sudo -n`,开头 re-exec /tmp 副本 |
| `0fe71bc`+`cf23814` | webhook spawn 的部署脚本被 systemd cgroup 株连(`restart cassia-socket` 把自己杀了)→ 改 `systemd-run` transient unit,脚本用绝对路径 |
| `530945c` | 模板构建同样被株连(`nohup &` 仍在 update.sh 的 unit 里,退出即被杀,trap 未跑导致 `.dockerignore` 遗失)→ 构建也走独立 `systemd-run --uid=ubuntu` |
| `d63dc59` | lite/desktop 并行构建 TOCTOU 互踩 `.dockerignore`(一个 mv 走,另一个 mv 失败 + trap 盖空文件)→ 两个 build.sh 用 `flock` 串行化 |

**根因教训**:webhook 触发的任何脚本只要碰到 `systemctl restart cassia-socket`
或「父进程退出」,就必须脱离调用者的 cgroup。以后新增这类脚本默认
`systemd-run`,不要 `nohup &`;动共享文件的并行任务默认 `flock`。
